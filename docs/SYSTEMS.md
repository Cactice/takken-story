# 宅建story システム仕様(第1世代・ありきた村)

> ストーリー全体像は [STORY.md](STORY.md)。当面の実装対象は**第1世代のみ**。
> 基礎中心・わかりやすさ・馴染みやすさ最優先。

## お金の単位
- **最小単位は1万円**。表示は「10万円」「100万円」のように万円単位(円表示はしない)
- 所持金の初期値: **10万円**
- **家賃は毎月5万円**(自宅を借りている間ずっと発生)

## 演出イベント(カットシーン)
**NPCがマップ上を自動で歩く演出**を、コードではなく**イベントデータで書けるようにする**。
オープニングも転入者の登場も、すべてこの仕組みで表現する。

イベントに `staging` を持たせ、順に実行する:
| 命令 | 意味 |
|---|---|
| `spawn` | キャラを指定位置(画面外可)に出す。`alert: true` で頭上に「!」 |
| `walkTo` | キャラを指定タイルまで自動で歩かせる(経路探索) |
| `lead` | キャラが先導し、**主人公がついていく**まで待つ(一定距離を保って進む) |
| `follow` | 指定キャラが**主人公の追従列に加わる** |
| `say` | セリフを表示 |
| `wait` | 一定時間待つ |
| `camera` | カメラを一時的に指定キャラへ寄せる |

## オープニング(チュートリアル)
いきなりマップに放り出さない。**上記の演出イベントで表現する**(コードに直書きしない)。
1. ハゲ田社長「ついて来い!」→ 社長が先導して歩き出す(`lead`)
2. 主人公が矢印キーでついていく。離れすぎると社長が立ち止まって待つ
3. 社長が主人公の**自宅**まで案内する。自宅はボロ屋
4. 家賃5万円/月、ここが拠点であることを説明
5. ここから自由行動開始

## 転入者の登場
- 会社に「!」が出て転入希望者が来る
- **転入者は画面外から歩いて登場**し、頭上に「!」を付けたまま**勝手に主人公を追従し始める**
- 話しかけると面談(要望のヒアリング)が始まり、物件案内へ

## マップとオブジェクト
- 建物の種類にバラエティを持たせる(木造アパート、マンション、一戸建て、農家、店舗、ボロ屋、空き地 など)
- **主人公の自宅**: ボロ屋。中に入れる(内装シーンあり)
- **会社(ひばり不動産)の建物**: 中に入れる。頭上に「!」が出ることがある
- **空き地**: 小さな看板を立て、スペースで土地の情報が見られる
- 建物に向かってスペース → **物件ステータス**表示(下記)

### 空き家と入居状況
- 建物には**それぞれ名前**がある(「ひばり荘」「ありきたハイツ」など)
- **開始時点で多くは埋まっている**。案内できる空き物件は3件前後に保つ(選択肢が多すぎると苦痛になる)
- 建物は**戸数**を持ち、**埋まり具合を表示**する(例:「3/8戸 入居中」)
  - **戸建は1戸**(母数1)。契約すると1軒まるごと埋まる
  - アパート4〜8戸、マンション10〜20戸
- **第1世代(ありきた村)は戸建が多い**。村なので当然で、1契約=1軒が埋まり、村が目に見えて埋まっていく
- 物件案内で契約が成立すると、その建物の空き戸が1つ埋まり、世帯がそこに住む

### 物件ステータス(建物・土地の情報)
建物/土地ごとに以下を持ち、スペースで一覧表示する:
- 構造(木造/鉄骨/RC)、階数、築年数、専有面積
- 用途地域、建蔽率、容積率
- 賃料/価格、敷金礼金
- 設備・特徴(防音、ペット可、日当たり、駅からの距離 など)
- 法的な注意点(再建築不可、市街化調整区域、接道 など)

## 住民と悩み
- **キャラは近くのマップオブジェクトに関連した悩みを話す**(マンションの苦情を言う人はマンションの前に置く)。逆に、悩みの種になるオブジェクトをキャラの近くに配置する
- キャラは**年齢**を持つ。時間経過で歳を取り、**死亡イベント**もある
- 一度悩みを解決したキャラは、二度目に話すと**その件について感謝**してくる
- イベントは1キャラ完結ではなく、**複数のキャラと建物が絡む**形を目指す

## 相談の流れ(改訂)
1. 住民が生活の悩みを話す(法律用語なし)
2. **ハゲ田の解説**: 問題を分解して教える。**図を出して解説する**(間取り図、境界線、建蔽率の面積図など簡単なSVG/ドット図)
3. **主人公の発言**: ハゲ田の解説をもとに、主人公が住民にわかりやすく説明する
4. **住民が感謝する**(反応は毎回必ず入れる)
5. 「ハゲ田のメモ」を1冊入手

## ハゲ田のメモ(本)システム
- 悩みを解決すると「ハゲ田のメモ」= 本(または紙)が1冊手に入り、**主人公の後ろをついてくる**
- 解決した数だけ本が連なってついてくる
- **自宅に入ると本が部屋の棚に並べられる**(ついてきた本は部屋に置かれ、身軽になる)
- 家の中で本の近くでスペース → **復習**ができる(いつでも復習可能)
- 本の表紙には**小さく住民の顔**が描いてある(ピクセル数を減らした簡易版でよい)

### メモの中身(図の参照)
メモは**イベントを参照するだけ**で、図やセリフを複製しない(二重管理を避ける)。
- メモが持つのは `eventId` と `memo: { title, summary }` だけ
- 復習画面を開いたら、その `eventId` のイベントから以下を**その場で組み立てて表示**する:
  1. **図** — イベントの `script[].diagram` を全部集めて表示(ハゲ田が解説に使った図がそのまま復習で見られる)
  2. **要点** — `memo.summary`
  3. **解説** — `quiz.explanation`(ハゲ田の口調のまま)
  4. **根拠条文** — `source`(条文コーパスへのリンク)
  5. **確認問題** — `quiz` を1問出す(テスト効果。間違えたら間隔反復の箱が戻る)
- 図はゲーム内の会話でも復習でも**同じコンポーネント**を使う(`src/components/diagram/`)
- 1つのイベントに複数の図があれば、矢印キーで図をめくれる

## 村の人口(コアループの中心)
- 村はできたばかりだが、**開始時から一定数の住民が住んでいる**(空っぽではない)。ほとんどの物件は埋まっており、**空きは3件前後**
- 住民は**物件案内で契約を成立させると増える**。契約した人がその物件に住み着き、村の住民になる
- 逆に**転出イベント**で住民が去ると空きが戻る。転入と転出で**空き物件が3件前後に保たれる**
- 住民が増えるほど相談イベントが増え、試験で解ける問題も増える
  → 「物件を案内して村を大きくする」ことが、そのまま学習量に直結する

## 会社と新キャラ転入
- 会社の建物に「!」が出る = **新しい転入希望者が来ている**サイン
- 会社に行くと転入者が待っている。**キャラの引越し理由も勉強になる**(ハゲ田のメモが発生する)
- 案内して契約成立 → その人が村の住民になる → 以後その人が相談イベントを持ってくる
- **転入者と住民は同一人物**として扱う(content/newcomers と content/characters を統合し、住民データに引越し情報を持たせる)

## 転入は「世帯」単位
転入者は1人とは限らない。**単身・カップル・家族(子供あり)・ルームシェア**などの世帯で来る。
- 世帯には**複数のメンバー**がいて、**それぞれ違う希望**を持つ
- 希望は**食い違ってよい**(夫は駅近、妻は静かな環境。親は広さ、子供は庭がほしい)。**折り合いのつく物件を探すのが腕の見せどころ**
- 内見中の**反応は全員分出す**(一人が気に入っても他が渋る、など)
- 契約すると**世帯全員が村の住民になる**(住民が一気に増える)
- 世帯構成そのものが学習の題材になる: 家族=面積・間取り、夫婦=共有名義や連帯債務、子供=学区・用途地域、ルームシェア=賃貸借の当事者、親との同居=相続

## 追従(ついてくる)システム
FFのように、**主人公のすぐ後ろを一列でついてくる**。専用モーダルではなくマップ上で完結させるための土台。
- 主人公が通ったタイルの履歴を保持し、1歩ずれで後続が同じ道をたどる
- 追従するもの: **案内中の転入世帯のメンバー**、**ハゲ田のメモ(本)**
- 追従キャラは移動の障害にならない(すり抜ける)
- **追従キャラに話しかけられる**: 隣接して向いてスペース → 要望の再確認、今見た物件の感想、雑談
- 本は解決した数だけ連なる。自宅に入ると棚に並び、身軽になる

## 物件案内(コアゲームプレイ)
転入世帯を**マップ上で連れ回して**物件を見せるゲーム。専用画面に飛ばさない。

### マップ上での流れ
1. 会社で世帯と面談し、要望を聞く → **世帯が主人公についてくる状態**になる
2. プレイヤーは自由に歩いて物件を回る
3. **建物に向かってスペース** → 物件ステータス表示 → **「この物件を内見しますか?」**
   - はい → **メンバー全員の反応**が出る。ハゲ田が法的な特徴を教えることもある(毎回ではない)
   - いいえ → 何も起きない(機嫌も減らない)
4. 内見の結果は**必ず2択**。機嫌が上がることはない(**機嫌は減るだけ**)
   - **要望に合う** → その場で「**この物件で契約しますか?**」と客から言ってくる → 35条書面の読み上げへ
   - **要望に合わない** → **機嫌が減る**。合わない度合いで減り幅を変える(嫌い=大きく、ピンと来ない=少し)。0になったら契約失敗
   - 一度内見した物件は、再度見ても機嫌は変動しない
5. 成立で世帯全員が村の住民になり、追従が解除される

### 客の機嫌(HP)
- **時間で減る。減りは速く**(のんびり歩き回っていると尽きる緊張感を出す)
- 要望に合わない物件を見せるとさらに減る(嫌い=大きく、ピンと来ない=少し)
- 35条書面の読み上げで質問に誤答するとさらに減る
- 尽きると契約失敗。**回復手段はない**

## 恋愛
- 対象は異性の住民。**同じ相手と何度も話す**ほど親密度が上がる
- 親密度が上がると**会話が少しずつ親密になる**(世間話 → 打ち解けた話 → 個人的な話)
- ある段階で相手が**それとなく「家を見に行きたい」**と言い出す → プレイヤーは**連れて行く / 行かない**を選べる
- 連れて行く = **デート**。中身は物件巡り(物件案内ゲームの流用)。ただし客のHPではなく**ときめき度**で判定する
- パートナーが**結婚したいと思うような家**を探すのがゴール。理想の結婚住宅像は人によって違う(広さ重視、日当たり重視、実家に近い、庭がほしい…)
- 良い家を提案できると関係が進展し、最終的に結婚 → 子供 → 世代交代へ繋がる

## その他の機能
- **主人公自身の売買・賃貸**: 2/4/5世代で可能(1世代目は対象外)
- 歩行アニメーション(主人公・住民)

## 物件の空き状況(選択肢を絞る)
物件が多すぎると、どれを見せるか決められず苦痛になる。**選べる物件は常に3件前後**に保つ。
- **ゲーム開始時から一定数の住民が住んでいる**(村は出来立てだが空っぽではない)。ほとんどの物件は埋まっている
- **空きがあるのは3件前後**。転入者を案内できるのはこの空き物件だけ
- **空き物件はマップ上で目立たせる**(枠のアウトライン、看板、光る等)。ひと目で「案内できる家」が分かること
- **物件ステータスの空き情報を目立たせる**(「空き 2/8戸」を大きく、色付きで。満室は明確にグレーアウト)
- 契約すると空きが減る → **転出イベント**で空きが戻る(下記)

## 転出イベント
住民が村を出ていく。**空きができたことをプレイヤーに把握させる**のが役目。
- 住民に呼ばれ、**引っ越す理由を聞く**。その理由が宅建の学習題材になる
  (転勤・相続で実家に戻る・借地契約の期間満了・立退き・建替え・施設入居 など)
- 理由に応じてハゲ田のアドバイス(メモ)が発生する
- 話が終わると住民が去り、**その物件が空きになる**。次の転入者を案内できる
- 転入と転出が交互に起きることで、**空き物件が3件前後に保たれる**

## 転入者の登場演出
新しい転入者が来るときは、**画面外から歩いてくる前に大きく告知**する。
- 「**転入者登場!**」のような大きな見出しを画面中央に出す(短く、勢いよく)
- そのあとに画面外から歩いて登場し、「!」を付けて追従を始める
- 何が起きたか分からないうちに人が増えている、という状態を避ける

## 試験は会場へ行って受ける(割り込みをなくす)
**試験を強制発生させない。プレイヤーが自分で会場へ行く。**
- **試験会場はひばり不動産(会社)**。試験日になったら**自分で歩いて中に入る**と受験できる
- 試験日が近づくと**予告**を出す(「あと3日で試験だ」)。当日は会社の頭上に「!」を出して分かるようにする
- 会場へ行かなければ受験できない(=その年は受けられない)。**取り逃がしを防ぐため予告は必ず出す**
- これにより、物件案内や会話の最中に試験が割り込むことが**構造的に起きない**

## 建物に入る
- **自宅(ボロ屋)**: 入るとメモが棚に並び、いつでも復習できる
- **会社(ひばり不動産)**: 中に入れる。**試験会場**であり、転入者との面談の場でもある
- **物件案内(転入者を連れている)最中は、自宅にも会社にも入れない**
  - 客を待たせて自分の家に帰るのは不自然だし、機嫌が減るだけで得もない
  - 入ろうとしたらハゲ田か客が止める(「今は客を待たせてるぞ」)
