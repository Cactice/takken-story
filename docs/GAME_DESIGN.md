# 宅建story ゲームデザイン仕様

## コンセプト
ポケモン風ドット絵の町。主人公は村の不動産屋で働く宅建士見習い。
住民がどんどん増え、相談・トラブルを解決しながら宅建の知識を学ぶ。

> **当面の実装対象は第1世代(ありきた村)のみ。** 5世代のストーリー全体は [STORY.md](STORY.md)、
> 第1世代の詳細システム(物件案内・ハゲ田のメモ・オープニング等)は [SYSTEMS.md](SYSTEMS.md) を参照。

## 主人公とライフサイクル
- 開始時に性別を選択(男/女)
- 15歳スタート。ゲーム内時間が経過する(**1年 = リアル10分**)
- 25〜35歳の間に結婚 → 子供が産まれる(恋愛要素は少しだけ)
- 子供が15歳になったら主人公は定年退職し、子供に世代交代
  - 子供が複数いる場合はプレイヤーが選択
- 複数世代を繰り返すのが前提の設計

## 会社と上司
- 舞台は「ひばり不動産」。**ハゲタ社長**(禿げ田さん・つるつる頭のおじさん)が一人で回してきたワンマン会社
- 主人公は創業以来初めて雇われた**第二社員**(社員2人目)。だからこそ社長が手取り足取り教えてくれるし、試験の答えも横流ししてくれる

## 世代ストーリー
- 1世代目: ひばり不動産の第二社員(見習い)としてハゲタ社長の下で働く
- 2世代目: 父/母の上司だった社長から不動産会社を譲ってもらう → ここから家族経営に
- 3世代目以降: 家族経営の会社を継いで資産を拡大していく

## 上司(メンター)役の継承
- 1世代目: 上司=ハゲタ社長
- **2世代目以降: 上司役=父または母(=プレイヤーが前の世代で操作していたキャラ)**。相談の分解・アドバイス・重説の未知論点の解説など、ハゲタがやっていた役割をそのまま先代が担う
- 実装ノート: セリフデータ内の話者名「ハゲタ「…」」は表示時に現世代のメンター名へ置換する(データは書き換えず、レンダリング時に `ハゲタ「` → `{メンター名}「` を差し替える)

## テスト(宅建試験)
- 年1回、ゲーム内10月に実施(実試験と同じ月で実在感を出す)
- 応募はゲーム内6月末まで。締切1ヶ月前から住民が「応募した?」と声をかける(リマインダーの物語化)。未応募で締切を過ぎた場合、1回だけ「社長の口利きで滑り込み」救済あり
- **1年目はハゲタ社長が強制的に申し込んでくれている**(応募操作なしで必ず受験できる。2年目から自分で応募する)
- 問題数10問: **ランダム出題はしない**(詳細は下記「年間サイクルと試験」)
- **1世代目**: 上司(社長)が内密に回答を横流ししてくれる(=チュートリアル的な救済。物語上は「見習いへの温情」、後の会社譲渡の伏線)
- **2世代目以降**: 横流しなし、自力で解く(先代から引き継いだ知識=プレイヤー自身の記憶が試される)
- 合格で大型ボーナス(年収数年分)+満点で称号。不合格でも小報酬で来年に接続
- 応募〜試験の約3ヶ月半(プレイ約17分)は模試・復習相談が増える「追い込み区間」(目標勾配効果)

## 宅建士の業務(合格後アンロック)
- 試験に合格して宅建士になると、**重要事項説明の読み上げ**の仕事が解禁される(それまではハゲタ社長しかできない=宅建士の独占業務であることをゲームで体感させる)
- 流れ: お客さんが来店 → 主人公が重要事項説明書を読み上げる → 成功で高額報酬
- **読み上げの構成: 1回の重説で3つの文面を読む**
  - 2つは体験済みの論点(馴染みのある内容=復習)
  - 1つは未体験の論点(未知の内容)。読み上げ後にハゲタ社長がその場で教えてくれる(=新しい論点との出会いの導線。相談イベントで拾いきれなかった論点もここでカバーできる)
- 合格前に挑戦しようとすると、ハゲタ「重説は宅建士にしかできん決まりだ。早く受かってこい」と断られる(独占業務の学習ポイント)
- 相談より単価が高い定期収入源として、資産1億への主要な稼ぎ手段になる

## 時間・エンゲージメント設計(研究ベース)
文献根拠の詳細は docs/ENGAGEMENT_RESEARCH.md 参照。

### 二重時計(設計の核)
- **ゲーム内時計**: 物語とモチベーションの装置。プレイ中のみ進む(オフラインで人生は進まない)。1ヶ月=50秒、1年=10分
- **リアル時計**: 記憶の間隔反復の管理専用。論点ごとにライトナー式(1日→3日→7日→14日→30日、誤答で戻る)。ゲーム内時間は学習間隔に使わない

### セッション設計
- 1セッション5〜10分想定。最小完結単位=相談1件約2分(状況説明30秒→クイズ1〜3問→解決演出30秒)
- 相談イベントの密度: ゲーム内1ヶ月に2〜4件
- オフライン中は「相談の予約」がリアル時間で溜まる(上限3件、溜め損ねペナルティなし)
- リアル1日1回「町の朝」ボーナス(最初の相談1件が報酬1.5倍)
- streak: 「1日相談1件」で継続。フリーズお守り月2個、目標日数は自己設定(非罰的運用)

### 報酬設計
- 相談正答: 固定基本料(難易度×固定額)+25〜30%の確率で1.5〜3倍の変動ボーナス
- 誤答: 罰なし。「後日また相談される」に変換(復習機会化)
- 資産1億は遠いので中間マイルストーン(100万→1000万→3000万…)の進捗バーを常時表示。世代交代直後は引き継ぎ資産で「押印済みスタンプ」効果

## 学習完結性(最重要要件)
このゲームだけで宅建試験の勉強が完結すること。
- 出題範囲(権利関係14問/宅建業法20問/法令上の制限8問/税・その他8問)の全論点を content/topics.md で網羅し、全論点に対応する相談イベント・試験問題を用意する
- 問題・解説は過去問レベルの正確さ。丸暗記でなく理解を促す(同じ論点を別の角度で再出題)
- 間隔反復(下記「二重時計」)で長期記憶に定着させる

## 目標
- メイン: 複数世代を経て、家族経営の不動産会社の資産を **1億円** にする
- やりこみ: **10億円** 到達で特別イベント

## 相談イベントの型(重要)
**相談の場ではクイズを出さない。** 相談=物語で学ぶ、クイズ=試験当日だけ。
- **住民**: 生活のわかりやすい悩みだけを話す。法律用語は一切使わない
- **上司ハゲタ**: 悩みを法律の問題に分解し、その場でアドバイスして解決(=explanation をアドバイスとして表示)。専門用語は必ず「◯◯(つまり△△のこと)」とかみ砕く
- **choices / correctChoice**: 相談では使わず、試験当日の問題として使う(経験した相談から出題)

## 年間サイクルと試験(改)
- **1年=10分**(1ヶ月=50秒)
- 1年の間に**約10件の相談イベント**が発生
- 試験は**常に10問固定**で、その年に予定された10イベントの論点から出題する。体験した相談は馴染みのある問題になり、話しそびれた相談の分は「見たことない問題」としてそのまま出る(例: 7人としか話さなかったら、馴染み7問+未知3問)。全部体験すれば満点が狙える
- **合格点は7割**
- HUDの右上に**日付メーター**(何月何日か)を常時表示し、**試験日は赤**でマークする

## コアループ
1. 住民が増える → 相談・トラブルが発生
2. 相談に答える(宅建の論点がベース)→ 報酬・知識
3. 6月末までに試験に応募 → 年1回の試験(10問)
4. 合格ボーナス・資産を積み上げる
5. 結婚・出産 → 子供15歳で世代交代
6. 世代をまたいで資産1億を目指す

## システム要素(実装対象)
- 時間システム: ゲーム内カレンダー(年/月/日)、リアル10分 = 1年
- 住民システム: 徐々に増える。各住民にキャラ設定と相談イベント
- 相談/トラブルイベント: 住民の悩み→ハゲタの図解→主人公の説明→感謝(クイズは試験のみ)
- 試験システム: 応募締切(6月末) → 受験 → 合否 → ボーナス
- 資産システム: お金の増減、目標1億/10億のマイルストーン
- 恋愛/結婚/出産: 25〜35歳の間、少しだけの恋愛要素
- 世代交代: 子供選択 → 主人公交代、資産は引き継ぎ
- セーブ: localStorage
