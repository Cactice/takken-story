# 図解のビジュアルデザイン ―「ハゲ田の野帳(やちょう)」

対象は `src/components/diagram/`。ハゲ田社長が相談中に出す図と、自宅の復習画面で見返す図は
**同じコンポーネント**を使う([SYSTEMS.md](SYSTEMS.md) 「メモの中身」)。

---

## 1. デザインの方向

### 選んだ方向: **昭和の不動産屋が方眼の野帳に描いた手控え × ゲームボーイの説明画面**

「クリーンでミニマル」は選ばない。この図は**ゲームの中の物**だからである。
プレイヤーが見ているのは抽象的なインフォグラフィックではなく、
**ハゲ田社長が目の前で野帳(測量・営業の現場で使う方眼のメモ帳)に描いてみせた図**という設定にする。

理由:

1. **物語の必然性がある。** 図の出所が「社長の手」だと決まっていれば、紙・方眼・インク・押した数字という
   要素が全部そこから導ける。装飾を足す必要がなくなる。
2. **ドット絵と喧嘩しない。** 方眼の目は **8px = 16pxタイルのちょうど半分**。図の中の格子と
   町のタイルの格子が同じリズムで刻まれる。
3. **教科書の図の読み方が使える。** 日本の学習参考書の図(面積の入れ子、日数の目盛、家系図の枝分かれ)は
   受験者にとって既に読める記法である。宅建の学習物なのだから、そこは発明しない。
4. **レトロな不動産チラシ**の要素(手描きの区画図・境界標・接道・領収書のような内訳)も同じ引き出しから出る。

### 実装上の最大の判断: **図の中の「人・家・土地・お金」はKenneyのドット絵そのもの**

棒人間も汎用アイコンも使わない。図に出てくる人物は**町を歩いているのと同じスプライト**、
家は**屋根タイル+壁タイルを積んだ実物**、地面は**草タイル・土タイルを敷き詰めたもの**である。
これが世界観の統一に一番効く。

- 役名(売主・買主・妻・長男…)には固定の顔を割り当てる (`tiles.ts` の `ROLE_TILE`)。
  割り当てのない名前は `lib/sprites.ts` と同じハッシュ配分に任せるので、同じ名前には常に同じ顔が出る。
- 「妻」に騎士の顔が出るような事故を防ぐのが `ROLE_TILE` の役目。

### 実装方式: SVGではなくHTML+CSS

外部ライブラリは使わない。SVGも使わない。理由は、

- SVG の `viewBox` で文字を描くと縮尺で文字サイズが変わり、**12px相当を下回る**ことを保証できない
- 日本語ラベルは長さが読めない。SVGのテキストは折り返せない
- ピクセルUIの実体は「箱と2〜3pxの枠線」であり、それはHTMLが最も素直に描ける

矢印の矢じりのような曲がった形だけ `clip-path` で階段状に切る。

## 2. 共通トークン(`tokens.css`)

すべての図はここの変数からしか値を取らない。図ごとに独自の色・線幅・フォントを持つことは**禁止**。

### パレット ― ドット絵素材から抽出

`public/assets/tiny-town/tilemap_packed.png` と `tiny-dungeon/tilemap_packed.png` の
実ピクセルを数えて頻出色を取った(= Endesga 32 パレット)。目で選んだ色は1つもない。

| 変数 | 値 | 役割 |
|---|---|---|
| `--dg-ink` | `#3f2631` | **スプライトの輪郭色と完全に同一。** 図の線・枠・文字すべて |
| `--dg-ink-2` | `#5a6988` | 補助線・注記 |
| `--dg-paper` | `#fdf6e3` | 野帳の紙 |
| `--dg-grid` | `#c0cbdc` | 方眼 |

`--dg-ink` をスプライトの輪郭と同じにしているのが肝で、これで CSS で描いた箱と
貼り込んだドット絵が「同じ人が同じペンで描いた1枚の絵」に見える。

### 意味の色(装飾では使わない)

| 変数 | 塗り / 縁 | 意味 |
|---|---|---|
| `--dg-own` | `#fdbe53` / `#e38628` | **所有** ― 本人・自分側の権利者・持分 |
| `--dg-right` | `#76e4ff` / `#0099db` | **権利** ― 相手方・契約関係・権利の対象 |
| `--dg-money` | `#fee761` / `#feae34` | **お金** ― 金額・支払い |
| `--dg-time` | `#f28462` / `#c34b35` | **期限** ― 期間・締切・境界線(越えてはいけない線) |
| `--dg-land` | `#84c669` / `#479f4a` | **実体** ― 土地・建物そのもの |
| `--dg-other` | `#c0cbdc` / `#8b9bb4` | 第三者・対象外・余り |

**色を「区別のため」に使ってはいけない。**
たとえば相続分の割合図は、妻も長男も長女も等しく「持分(=所有)」なので**全部同じ橙**にする。
隣り合う区画は色ではなく **市松のディザ(網掛け)** で見分ける。これはドット絵の減色表現そのままの手法で、
「色が違う=意味が違う」という規律を壊さずに区別を作れる。

### 目盛

すべて4の倍数(16pxタイルの1/4)。

| 変数 | 値 | 用途 |
|---|---|---|
| `--dg-line` | `3px` | **枠線・箱線の太さ。図の中に線の太さは1種類しかない** |
| `--dg-cell` | `8px` | 方眼の目 = タイルの半分 |
| `--dg-gap` / `--dg-gap-lg` | `8px` / `16px` | 部品どうし / まとまりどうし |
| `--dg-pad` | `12px`(lg は `16px`) | 紙の余白 |
| `--dg-sprite` | `24px`(lg は `32px`) | ドット絵チップ(16px の 1.5倍 / 2倍) |

余白のリズムは **8 → 16** の2段だけ。均一なパディングを全部に配らず、
「部品の間は8」「まとまりの間は16」で階層をつける。

### 角の処理: ピクセルの階段

角丸は使わない。箱は `border` ではなく **4方向の `box-shadow`** で枠を描く。
これは古典的なピクセルUIの手法で、**角の4pxが自動的に欠ける**ため、
拡大しても滑らかにならない「ドット絵の箱」になる。

```css
box-shadow:
  0 -3px 0 0 var(--dg-ink), 0 3px 0 0 var(--dg-ink),
  -3px 0 0 0 var(--dg-ink), 3px 0 0 0 var(--dg-ink);
```

見出しタブ・矢じり・期限のピンは `clip-path: polygon()` で**斜辺ではなく段差**に切る。

### フォント: 2書体の役割分担

| 変数 | 書体 | 使うもの |
|---|---|---|
| `--dg-font-dot` | **DotGothic16** (SIL OFL 1.1, 自前ホスト) | 数値・単位・見出しタブ。**野帳に押した数字** |
| (継承) | Hiragino Maru Gothic ProN 等の丸ゴシック | 人名・区画名・注記。**手で書いた語句** |

- ドットフォントは**16px設計なので16px(lgの合計欄だけ32px)の等倍でしか使わない**。
  半端なサイズで使うとアンチエイリアスでボケて、ドット絵の隣で汚くなる。
- 日本語の語句まで全部ドットにすると可読性が落ちるので、**数字だけがドット**という分担にした。
  「数値は野帳に押した数字、語句は手書き」という物語上の説明もつく。
- Google Fonts の unicode-range 分割をそのまま自前ホストしているので、
  **実際に使った字のサブセットしか落ちてこない**(計測値: 9ファイル / 47KB)。
  vite の `base` を解決するため `<link>` は `useDotFont.ts` から挿す。

### 文字サイズ

| 変数 | sm | lg |
|---|---|---|
| `--dg-fs-num` | 16px | 16px |
| `--dg-fs-num-lg` | 24px | 32px |
| `--dg-fs-label` | 13px | 15px |
| `--dg-fs-note` | 12px | 13px |

**最小12px。それ以下は作らない。** 階層はサイズではなく、色・箱・位置で作る。

### アニメーション

compositor で完結する `transform` / `opacity` のみ。イージングは **`steps()`** を使う。
連続的なカーブではなく2〜3コマの離散的な動きにすることで、スプライトアニメーションと同じ質感になる。

- 図の登場: `opacity` + `translateY(6px)`、140ms / `steps(3, end)`
- 硬貨の上下: `translateY(-3px)`、900ms / `steps(2, end)`
- どちらも `prefers-reduced-motion: reduce` で停止

## 3. 共通プリミティブ(`primitives.tsx`)

各図はこれの組み合わせだけで書く。

| 部品 | 役割 |
|---|---|
| `Sheet` | 野帳の1ページ。方眼 + インクの枠 + 見出しタブ + 凡例 + 読み上げ用の要約文 |
| `Box` | ラベル箱。`role` で意味の色が決まる |
| `Num` | 数値。ドットフォント・等幅数字 |
| `Person` | 人物チップ(Kenney のキャラタイル) |
| `House` / `Storeys` | 建物チップ(屋根+壁を積む) / 階数ぶん積んだ側面 |
| `Sign` / `Coins` | 境界標の看板 / 硬貨 |
| `Arrow` | 矢印。`role` で色、`dashed` で見えない関係 |
| `LegendItem` | 凡例の1項目 |

`Sheet` は必ず `summary`(その図が言っていることの一文)を要求する。
図は `role="group"` + `aria-label` を持ち、読み上げでも意味が通る。

## 4. 各図の見た目

| type | 見た目 | データの読み方 |
|---|---|---|
| `parties` | 起点の人物から**幹線(縦線)が伸びて枝分かれ**する家系図。全員がドット絵の顔つき | `labels[0]`=起点、以降=相手方。2人なら1本の矢印、3人以上なら扇 |
| `ratio` | 横1本の積み上げ帯。**全区画が同じ橙(=どれも持分)**で、隣どうしは市松のディザで区別。下に `0 / 1/4 / 1/2 / 3/4 / 全部` の物差し。凡例には**分数**を出す(`50% → 1/2`) | `labels` + `values`(合計100) |
| `area` | 左=真上から見た敷地(草タイル)に建築面積の橙を**左下寄せ**で置き、家を1軒建てる。右=土の地面に**壁タイルを階数ぶん積んだ側面図** | `values[0]`=建蔽率%, `values[1]`=容積率%。階数 = 容積率÷建蔽率 |
| `timeline` | 太い帯の物差し。**31日以内なら1日ごとの目盛が入る**。起点=橙のピン、期限=赤のピン、間を赤で塗る。札は上下交互、両端は内側に寄せてはみ出さない | `labels`=時点、`values`=起点からの日数 |
| `money` | 払う人 →(硬貨+金額)→ 受け取る人。下に**領収書のような内訳の台帳**(右揃え・二重罫の合計) | `labels[0]`=払う人, `[1]`=受け取る人, `[2..]`=内訳の名目, `values`=金額(万円) |
| `land` | 草を敷いた区画を横に並べ、**間に赤い破線の境界線と境界標の看板**。下辺に土の道路 | `labels[0]`=自分の土地、以降=隣地。`values`=面積㎡ |
| `floorplan` | 3列×2行の**不均等なグリッド**(1部屋が2マスを占める等)で本物の間取りらしく組む。床はタイル。外壁の左下に玄関 | `labels`=部屋名, `values`=面積㎡ |

### 2サイズ

`<Diagram spec={...} size="sm" />`(会話ウィンドウ / 既定)と `size="lg"`(復習画面)。
`.dg-lg` がトークンを差し替えるだけで、レイアウトの分岐は持たない。

- sm: 最大 26rem、チップ24px、余白12px
- lg: 最大 34rem、中央寄せ、チップ32px、余白16px

**上限を必ず持たせる**のが重要で、そうしないと復習画面で図が横に間延びして関係が読めなくなる。
狭い画面では紙の中だけが横スクロールし(`.dg-sheet { overflow-x: auto }`)、
**ページ本体には横スクロールを出さない**(360px幅で検証済み)。

## 5. やってはいけないこと

- 色を意味以外(区別・装飾・かわいさ)に使う → 区別が要るときは**ディザ**を使う
- `--dg-line` 以外の線の太さを増やす
- 角丸を使う
- ドットフォントを16px以外(lgの合計32pxを除く)で使う
- 12px未満の文字
- 図ごとに独自のクラス・色・余白を作る(`diagram.css` に書くのは**レイアウトだけ**)
- SVG や外部ライブラリを持ち込む
